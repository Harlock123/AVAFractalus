# AGENTS.md

Notes for anyone, human or AI agent, changing this code. `README.md` covers playing the game, its controls and
what the tests check; this file covers how the code is put together and the rules that keep it working.

## What this is

A first-person rescue mission over fractal mountains in the style of Lucasfilm Games' 1985 game Rescue on
Fractalus!, in C# on .NET 10 and Avalonia 12, drawn through Avalonia's `DrawingContext`. One self-contained executable per platform
(Windows, macOS and Linux, x64 and ARM). Everything in it is original: the graphics are drawn in code, and the
sounds, music and the ship's voice are synthesised by `tools/make_sounds.py` (the voice through `tools/speech.py`).

## Commands

```bash
dotnet build AVAFractalus.slnx                    # the SDK version is in global.json (10.0.400 or later)
dotnet test AVAFractalus.slnx                     # every test runs headless: no window opens
dotnet run --project src/AVAFractalus             # play it; --no-audio for silence
FRACTALUS_SHOTS=$PWD/Images dotnet test tests/AVAFractalus.Tests --filter ScreenshotTests   # refresh the README's pictures
FRACTALUS_PROBE=1 dotnet test tests/AVAFractalus.Tests --filter PilotProbe   # how the computer pilot fares, for tuning
python3 tools/make_sounds.py                      # rebuild src/AVAFractalus/Sounds (standard-library Python only)
```

`Directory.Build.props` sets `TreatWarningsAsErrors`, nullable reference types and implicit usings for every
project: a warning fails the build, so keep it at zero.

## Layout

- `src/AVAFractalus/Engine/`: the game, with no Avalonia drawing in it.
  - `GameEngine.cs` runs the states (title, attract, play, pause, game over, initials, high scores) and the
    fixed-step loop.
  - `Sim.cs` steps a planet: flying, landing and lifting off, the pilots and Jaggi at the airlock, the guns,
    the saucers and the climb to the mother ship.
  - `Planet.cs` has `Controls`, the measures (`Field`) and the planets: a fractal height map, the pilots and
    the guns, built from a seed.
  - `World.cs` has the seeded `Dice` and the things on a planet.
  - `Autopilot.cs` is the computer pilot, used by the attract mode and the tests.
  - `InputHandler.cs` (keys) and `ControllerManager.cs` (SDL2 gamepads) produce `Controls`.
  - `HighScoreTable.cs`, `InitialsEntry.cs` and `SoundManager.cs` do what their names say.
- `src/AVAFractalus/Views/`: `GameCanvas` (split over two partial files) draws the 1024x768 frame and the
  instrument panel, and runs the 60 Hz timer. `Renderer.cs` draws the cockpit view a pixel at a time by ray
  marching each screen column over the height map.
- `src/AVAFractalus/Audio/`: the OpenAL Soft audio engine, shared with the author's other AVA games.
- `src/AVAFractalus/Sounds/`: the WAV files the game plays, generated by `tools/make_sounds.py`.
- `tests/AVAFractalus.Tests/`: xUnit v3 with `Avalonia.Headless.XUnit`: `GameplayTests`, `PlanetTests`,
  `ScreenshotTests` and the opt-in `PilotProbe`.

## Rules that keep it working

- **Fixed steps.** `GameEngine.Update` advances the game in fixed 1/60 s steps (`Sim.Step`, `Field.Step`),
  independent of the frame rate, so tests can play whole planets deterministically from a seed. Draw random
  numbers from the world's seeded `Dice` (`w.Dice`), never from `Random.Shared`.
- **Engine first, drawing second.** Gameplay belongs in `Engine/`, where tests can reach it without a window.
  `Views/` only reads the world and draws it.
- **Input goes through `InputHandler`.** Up/down on keys and stick must produce the same `dy` sign the engine
  expects (negative is up the screen, which climbs). Test new controls through `InputHandler`, not by setting
  `Controls` directly.
- **SDL under one lock.** `ControllerManager` starts, polls and stops SDL only inside `lock (Sdl)`. The tests
  create many handlers in parallel, and unlocked SDL calls corrupt its heap.
- **Audio.** OpenAL Soft through Silk.NET. `Directory.Build.targets` swaps in the official Windows `soft_oal.dll`
  from `Audio/native/`, which needs no Visual C++ runtime. In a virtual machine `OpenAlConfig` writes a larger
  mixing period to `ALSOFT_CONF` so the sound doesn't break up.
- **Tests never touch the player's files.** High scores live in the app-data folder (`AVAFractalus`); tests
  load the table from a temporary folder and run silent (`Silent = true`).

## Making a change

- Add or update tests with every gameplay change. `dotnet test` must pass, with no warnings.
- If the change shows on screen, refresh the screenshots with the command above, and look at them.
- Update `README.md` (features, controls, the test list) to match.
- New sounds and spoken words go into `tools/make_sounds.py`, not as hand-edited WAV files.

## CI and releases

`.github/workflows/build.yml` builds and tests every push. It then publishes self-contained single-file builds for
win-x64/x86/arm64, linux-x64/arm64/arm and osx-x64/arm64. Every run keeps the builds as workflow artifacts.
Only pushes to `main` replace the assets of the `latest` pre-release, and a `v*` tag makes a proper release.
A release run then asks the portfolio site to rebuild, if the `SITE_REFRESH_TOKEN` secret is set.
